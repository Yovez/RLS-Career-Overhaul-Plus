## What to build

Lock the Payment Domain facade as the single source of truth for affordability and debit: given Wallet, Accounts, and auto-pay config, `canPay`, `getSpendableMoney`, `pay`, and the reward path follow Wallet + Accounts rules (Spendable derived only). Ship facade-level checks for auto-pay on/off, checking-then-Wallet split, wrong spend bucket ignored, and Spendable never persisted as a third balance.

## Acceptance criteria

- [ ] Facade behavior matches glossary: Wallet and Accounts stored; Spendable derived per reason
- [ ] Auto-pay on: enough checking alone → canPay true; pay debits checking first
- [ ] Auto-pay on: partial checking → pay splits checking then Wallet
- [ ] Auto-pay off for that bucket → Spendable equals Wallet; checking untouched on pay
- [ ] Wrong bucket does not use another category's pay claim
- [ ] Spendable never exceeds Wallet + claimed checking for that reason
- [ ] Failed/rejected pay does not leave a partial checking debit without completing the purchase
- [ ] Automated or reproducible facade checklist covers the cases above
